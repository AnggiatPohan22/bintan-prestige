# Security Skill

## Main Goal
Protect the CMS from common web attacks, backdoors, leaked secrets, unsafe uploads, and unauthorized backend access.

## Security Layers

### 1. Environment Security
- Never commit .env
- Never expose APP_KEY
- Never expose database credentials
- Never expose API tokens
- APP_DEBUG must be false in production
- APP_ENV must be production in hosting
- Use secure APP_KEY generated by artisan key:generate

### 2. GitHub Secret Safety
- Check if sensitive data has been committed.
- Recommend GitHub secret scanning and push protection.
- If secret was committed, rotate it immediately.
- Removing a secret from current files is not enough if it exists in Git history.

### 3. Backend Access Security
- Admin routes must use auth middleware.
- Use role/permission checks.
- Use policies/gates for sensitive actions.
- Protect delete/update routes.
- Rate limit login and sensitive endpoints.
- Log suspicious actions.

### 4. Query Security
- Use Eloquent/Query Builder.
- Avoid raw SQL.
- Never concatenate user input into SQL.
- Use allowlist for sort/filter fields.
- Validate every request using Form Request.

### 5. Upload Security
- Validate mime type.
- Validate file size.
- Validate extension.
- Store uploads outside executable paths when possible.
- Rename uploaded files.
- Do not trust original filename.
- Block php, js, exe, sh, bat, svg unless explicitly sanitized.
- Optimize images on upload.

### 6. XSS/CSRF Security
- Use Blade escaping by default.
- Avoid raw HTML output.
- Use CSRF tokens for forms.
- Sanitize rich text fields if allowed.

### 7. Backdoor Audit
AI must scan for:
- eval
- shell_exec
- exec
- system
- passthru
- base64_decode misuse
- remote file include
- suspicious hidden admin route
- unknown middleware bypass
- unexpected user creation
- public writable PHP files
- suspicious cron/scheduler commands

## Forbidden
- No hardcoded credentials.
- No public debug route.
- No hidden superadmin.
- No bypass login route.
- No unsafe upload handler.
