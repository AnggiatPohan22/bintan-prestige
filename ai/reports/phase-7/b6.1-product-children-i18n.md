## Task: B6.1 — Extend catalog i18n to Product's 5 child sections + `duration`

B6 localized Product's own copy columns but stopped at the parent row. This
task carries the same pattern to the five child sections — Highlights,
Features, FAQs, Itineraries, Notes — plus the parent's `duration` field which
was originally excluded (owner confirmed it's free-form copy: "4 jam" vs
"4 hours").

Owner-approved decisions on ambiguous fields:
- `Product.duration` → **translated** (free-form label).
- `ProductFeature.label` → **system key** (kept shared for filter/grouping;
  `"included"` / `"excluded"` etc.). Only `value` is translated.
- `ProductItinerary.time` → **translated** (label like "Morning" / "Pagi").
  `start_time` (integer clock) stays shared.
- Admin UI → **inline per-row** in each Edit modal (matches B6 pattern; no
  separate translation page).

### Design notes
- **`ChildTranslations` helper.** 5 controllers × 2 methods = 10 sites for
  translation persistence. Extracting the pattern into a helper (rulesFor +
  syncFromRequest) keeps each site to one-line changes, and centralizes the
  allow-list-per-model discipline. Trait check makes misuse a silent no-op
  instead of a fatal.
- **Base column in admin.** `getRawOriginal()` — same pattern as B7 for menu
  labels. Otherwise `$feature->value` in the list would render the localized
  string when the admin app locale ever drifts to non-default, which is
  confusing for an EN-only admin.
- **`ProductFeature.label` stays a system key.** Filtering (`->where('label',
  'included')`) and grouping (`includedFeatures()` scope) MUST work identically
  across locales. Translating `label` would break these — enforced by an
  explicit assertion in `test_feature_value_localizes_but_label_is_shared`.
- **`ProductItinerary.start_time` stays shared.** It's an integer clock, not a
  label. `time` (the free-form label like "Morning") is translated; `start_time`
  is not. Assertion in
  `test_itinerary_time_title_description_localize_but_start_time_is_shared`.

### Impact
- DB: **none** (uses B1's `translations` table).
- Routes: none (existing child CRUD routes accept the extra `translations` block).
- Frontend: product detail cards / rows render in the active locale; default

- Security: admin-guarded; only allow-listed fields per model are persisted;
  empty clears the sidecar row.
